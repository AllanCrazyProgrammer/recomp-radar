# Cuenta y amigos en Firebase

Los perfiles usan `publicProfiles/{uid}` con alias permanente, visibilidad opt-in y sin correo. La búsqueda es exacta. Las relaciones se guardan en `users/{uid}/friends/{peerUid}`. Una solicitud crea un registro pendiente en la cuenta destino y un registro saliente del solicitante. La persona destino acepta o rechaza; solo la aceptación crea el estado `friend` en ambos lados. Bloquear crea un registro bajo `users/{uid}/blocks/{peerUid}` y cierra los registros relacionados. Las reglas niegan solicitudes entre cuentas bloqueadas.

Las reglas validan quién puede crear una solicitud, quién puede aceptarla y que el estado aceptado se escriba en ambos registros dentro de una misma operación atómica. Un estado de amistad aislado no concede acceso. `accepted(ownerUid)` también verifica que no haya un bloqueo en ninguna dirección. Un amigo puede leer únicamente `users/{ownerUid}/targets`; instalaciones, releases guardadas, covers, perfil privado y actividad quedan privados.

Firebase Spark no tiene backend para límites sociales persistentes ni para garantizar unicidad de alias. La interfaz comprueba alias disponibles antes de guardarlos, pero dos altas simultáneas pueden elegir el mismo alias. No se muestra el email. Los perfiles, relaciones, datos y covers se borran manualmente desde Firebase Console si se elimina una cuenta; la app no tiene operación de borrado de cuenta.
